# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Crazy Face is a browser-only toy: take or upload a photo, then squish, stretch and pull the face around (WebGL2). It is plain TypeScript + Vite with no framework, no backend and no tests. `NEXT_STEPS.md` has the roadmap of pending features and known issues. Docs are split: `README.md` is for players (what the app is and its features, no code details); `docs/DEVELOPMENT.md` is for developers (stack, how features work, running and building). Update both when a feature changes.

## Commands

```bash
npm install
npm run dev          # http://localhost:5173
npm run dev:phone    # HTTPS on the LAN (self-signed cert via @vitejs/plugin-basic-ssl); needed to test the camera on a phone
npm run build        # tsc --noEmit + vite build → dist/. This is the only check; it must pass before committing
npx vite preview --port 4173   # serve the build
```

There is no linter or test runner. `tsconfig.json` is strict with `noUnusedLocals`/`noUnusedParameters`, so unused code fails the build.

Pushes to `main` deploy to GitHub Pages (`.github/workflows/deploy.yml`). `vite.config.ts` uses `base: './'` so the build works under `/crazy-face/`.

### Browser testing (Playwright, headless)

- Launch Chromium with `--use-gl=swiftshader --enable-unsafe-swiftshader` so WebGL2 works.
- For the camera, also pass `--use-fake-device-for-media-stream --use-fake-ui-for-media-stream`.
- To load a test photo: draw it on a canvas inside the page, put it in a `DataTransfer`, set that on `#file`, and dispatch `change`.

## Project rules

- **The app speaks Brazilian Portuguese (PT-BR, the source language) and English.** Every user-facing string (buttons, hints, alerts, `aria-label`s, `title`s) must exist in both `src/locales/pt.ts` and `src/locales/en.ts`; `en` is typed as `Messages = typeof pt`, so a missing key fails the build. Jokes are written for each language (Brazilian humor in PT, natural English in EN), not translated word for word, and the lists may differ in length. Code, comments, commits and the docs stay in English.
- **i18n (`src/i18n.ts`, no library).** `t()` returns the current locale's messages (`t().text.x`, `pick(t().hints)`); read it when the text is shown, never cache it in a module constant. Static markup in `index.html` keeps the PT-BR text as the default and names its key with `data-i18n` (textContent), `data-i18n-aria` and `data-i18n-title` (keys in `dom`); text next to a form control goes in its own `<span data-i18n>`. `applyDom()` fills them. Text set from code that stays on screen must be redrawn in an `onLocaleChange()` listener. The language comes from `?lang=pt|en`, then the saved choice (`localStorage`), then `navigator.languages`, falling back to English. The 🌐 PT | EN picker is always visible (toolbar and start screen; `[data-lang]` buttons, `setupLanguagePicker()`), and switching keeps the photo and its warps. There are no pop-up captions: they were removed on purpose.
- Sounds are generated with the Web Audio API in `src/sound.ts` (no audio files). Add new sounds as methods on `Sounds`.
- Photos never leave the device: no uploads, no servers. ML runs locally (face detection in `src/faces.ts`), and its library, wasm and model are bundled with the app, not loaded from a CDN.
- No frameworks or UI libraries.

## Architecture

**World units.** Everything geometric is in world units: the image is 1 unit wide and `aspect` (height/width) units tall. `Layout` (`{offsetX, offsetY, scale}` in `src/renderer.ts`) maps world units to canvas CSS pixels. `main.ts` computes it in `updateLayout()` (image fit at 80% of the stage so there's room to stretch) and converts pointers with `toWorld()`.

**Data flow.**
- `src/main.ts` is the composition root. It owns the single `WarpMesh` and `Layout`, wires all DOM controls, handles pointer events (multi-touch via a `drags` map keyed by `pointerId`), shows the "ouch" bubble when a stretch goes too far, and runs the `requestAnimationFrame` loop: `mesh.update(dt, now)` then `renderer.draw(mesh, layout)`.
- **Two screens.** The app opens on the start screen (`#start`: 📸 Tirar foto, 🖼️ Escolher foto, or the sample face). Once a photo arrives, `showEditor()` hides it and un-inerts the toolbar, stage and bottom dock (effects strip, then 📸 Nova foto · ⚙️ Ajustes · 📤 Compartilhar com amigos; ⚙️ Ajustes is a sheet with ✂️, ✨, Modo massinha, 🎉 and Pincel; 📤 is a sheet with 💾 Salvar na galeria, 💬 Enviar no WhatsApp and 🔗 Compartilhar o link do Crazy Face, each with a line saying what it sends; one sheet open at a time (`sheets`, `closeSheets()`); ↺ Resetar floats on the top-right corner of the stage, always visible); **📸 Nova foto** calls `showStart()` to go back (with "Voltar para a foto de antes"). The cartoon face is loaded behind the start screen so the mesh always exists. There is no live video texture: effects work on still photos only (a live mirror was removed because mesh effects can't follow moving faces).
- `setImage()` in `main.ts` is the single entry point for a new photo: it uploads the texture and calls `newMesh()`, which **creates a new `WarpMesh`** (so the mesh reference changes), and starts the face search. Callers then call `showEditor()`. `photo` holds the current photo. Modules that need the mesh get it through a getter (`getMesh: () => mesh`), never by holding a reference.
- `src/warp.ts` (`WarpMesh`) is the physics: a grid of points (64 columns) with rest and current positions, integrated at a fixed 1/120 s step with a damped spring back to rest. `grab/move/release` handle dragging with a falloff radius. `clay` disables the spring (Modo massinha, checked by default in `index.html`, so new meshes start with it on). `playEffect(kind, now, target?)` runs a timed preset (ramp + hold) as a displacement on top of the current positions; several can run at once, and `target: {x, y, r}` aims one at a face. `chaos`, `poke` and `shake` are impulse helpers. The `eyes`/`nose`/`cheeks`/`smile` kinds are not mesh moves: they go to `mesh.lenses` (`src/lens.ts`), magnifying bulges in the photo's rest space that the renderer draws per pixel in the fragment shader (uniform arrays, up to `MAX_LENSES`). They aim at `EffectTarget.landmarks`, or landmarks guessed from the circle.
- `src/renderer.ts` (`Renderer`) is raw WebGL2: one textured triangle grid whose vertex buffer is re-uploaded from `mesh.positions` each frame, and whose fragment shader remaps texture lookups for the lenses. `setImage(source)` uploads a texture with mipmaps. **Salvar foto** and 📤 Compartilhar use `exportJpeg(mesh, sticker)`: it redraws offscreen (multisampled framebuffer, then `readPixels`) at the photo texture's own pixels per world unit (long side ≤ 4096), cropped to the warped mesh and sticker plus a 2% margin, on white, and encodes a JPEG at 0.9. It doesn't read the on-screen canvas, so there's no `preserveDrawingBuffer`, and DOM overlays like the "ouch" bubble aren't in it.
- `src/beauty.ts` (✨ Luz e beleza): `measureTone(image)` reads a 96 px histogram (levels, gamma towards a 0.46 median, partial gray-world balance, denoise amount); `enhancePhoto(image, tone, faces?)` runs one pass in its own offscreen WebGL2 context and returns a new canvas: light fix and colour denoise everywhere, plus a strong skin smoothing (two bilateral passes, YCbCr skin mask, eyes/mouth kept sharp), a soft light and a warm glow inside each face. In `main.ts`, `setImage(image, {findFaces, beauty, lit})` keeps the original `photo`; the filter is on for camera photos (unless turned off in the review) and for dark gallery photos (`isDark`). Faces are detected on the brightened copy; `showLook()` swaps only the texture (the mesh and its warps stay) when the toggle changes or faces arrive.
- `src/crop.ts` (✂️ Recortar, optional): `setupCropper(sounds)` returns a `Cropper`, `(image, start?) => Promise<Crop | null>`, a full-screen dialog with a draggable box (corners resize, inside moves), Livre / 1:1 / 3:4 / 4:3 / 9:16 and quarter turns. A `Crop` is `{turns, x, y, w, h}`: clockwise quarter turns, then a box in fractions of the turned photo, so the same crop fits the photo and its brightened copy. `applyCrop(image, crop)` makes the new canvas. Cropping happens **before** `setImage()`, so the mesh, faces and ✨ only see the cropped photo. `main.ts` keeps `photoFraming` (`{source, crop}`, the uncropped photo) so a new crop from ⚙️ Ajustes can grow back; it creates a new mesh, so warps reset. The cartoon can't be cropped. The camera review has its own ✂️ chip and passes the framing to `onPhoto`.
- `src/sticker.ts` (🎉 Sextou, Fridays only): `isFriday()` checks the device's local day (`?sextou=1` / `?sextou=0` force it for testing). `drawSticker(text)` draws the label on a 2D canvas; `Sticker` holds its pose in world units and handles the gestures (drag, two-finger pinch to resize and rotate, mouse wheel, tap). The renderer draws it as a second textured quad after the mesh (`renderer.setSticker`, `draw(mesh, layout, pose)`), so it's in **Salvar foto** and 📤 shares; it isn't warped by the mesh. In `main.ts`, `setImage()` calls `placeSticker()` (new text, top centre; `sticker.avoid(faces)` slides it off the faces when they arrive, unless the user moved it); pointer handlers give the sticker first pick (`sticker.wants`), and a tap wiggles it and plays `sounds.party()`. The 🎉 Sextou toggle in ⚙️ Ajustes only shows on Fridays. 💬 Enviar no WhatsApp sends the photo with an invite line (`share`) plus the site link (`siteLink()`): the share sheet on phones; on computers the photo goes to the clipboard and `wa.me` opens with the text (a download if the clipboard fails). 🔗 sends only the link with an `invite` line. 💾 downloads (the share sheet's "Save Image" on iOS).
- `src/image.ts`: `loadImageFile` and `fitToCanvas` (downscale + optional mirroring) normalize every source to an `HTMLCanvasElement`; `drawDefaultFace` draws the built-in cartoon face.
- `src/faces.ts`: `detectFaces(image, max, {quick})` lazily imports `@mediapipe/tasks-vision` (its own chunk) and runs BlazeFace over the whole photo plus half-overlapping square windows of shrinking size, then merges duplicates. Results are circles in world units, biggest first, with BlazeFace's eye/nose/mouth keypoints as `landmarks`. `quick` stops after the biggest windows (a few runs, ~1 s on desktop; fine for selfies). `preloadFaceDetector()` starts the download early (when the camera or gallery opens).
- **Faces (automatic only, no manual marking).** `setImage()` calls `searchFaces()`: a quick detection sets `photoFaces` right away (`facesReady` resolves here), then a full detection runs in the background and replaces it if it finds at least as many faces (small faces in group photos). The effect buttons (`playPreset`, via `targetsFor`) call `playEffect(kind, now, face)` on **every** face in `photoFaces` (up to `MAX_FACES` = 6), falling back to the whole image. 🎭 Um efeito pra cada (`playMix`) gives each face a different kind. With 2+ faces, the hint says the effects hit everyone. The cartoon face skips detection (`setImage(image, false)`); 👀/👃/🐹/😁 use its known features (`DEFAULT_FACE_TARGET`), and on a photo with no face they do nothing.
- Feature modules use a setup function with injected dependencies instead of importing `main.ts`:
  - `setupCamera(onPhoto, sounds, cropper)` in `src/camera.ts`: full-screen `getUserMedia` overlay with a countdown, flash, camera flip, a mirrored selfie, a "Ficou boa?" review (✔ Usar esta / 🔁 Tirar outra, with a ✨ Com luz e beleza / Sem filtro chip and ✂️ Recortar), 💡 light (a warm glowing screen around a smaller preview on the front camera, the whole screen lit for the last countdown second; the torch on the back camera when it has one; turns on by itself in a dark room), a preview brightened with a CSS filter to match the photo, continuous exposure/white balance and +1 EV in the dark where `getCapabilities()` offers them, and a fallback to `<input capture>`. The shot uses `ImageCapture.takePhoto()` (full sensor resolution) where available, else the current video frame. It stops the stream when the photo is used, on close or on tab hide (a photo in review is kept). `onPhoto(photo, lit, framing)` gets the cropped photo and its framing; the editor opens on it with no effect. (The 😜 Desafio de pose, a pose prompt whose effect played after the shot, was removed.)
